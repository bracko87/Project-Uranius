## Source-aligned business rules (paraphrased)

- Cash generation takes race entry prize_fund_cash and category format. Stage finish award is rounded numeric fund * bucket share / 100 / scheduled stage count * rank share / 100. One-day finish and final buckets have no stage-count divisor. Rule key is (race class, bucket). Top_n and rank-distribution array determine eligibility and amount. Stage race final generation includes all stage finish rows plus final general, points, mountain, young, team buckets. One-day final includes team bucket. Rider-based cash awards credit team recipients. World Road Championship metadata branch suppresses ordinary cash prizes and ranking awards. Current prize generator upserts source rows, including amount, and preserves paid status; no paid rows deliberately deleted. Payment only iterates positive pending awards for requested race/stage; developing squad sporting identity is retained, but cash goes to parent/main club when present. Finance primitive uses award ID, not race ID, for event lock when supplied, credits treasury/club double entry, then configured tax withholding. No rate or actual award schedules read.
- Ranking generator resolves category, joins rule key (class, source type, rank). Stage race stage-finish, daily GC leader (rank 1), final GC; one-day finish. Equal rider/team points per matched ordinary result; excluded finish statuses include DNF/DNS/DSQ/OTL and synonyms. Individual awards normalization remains a separate rule. Current stage rows refreshed; final GC rows replaced only on final. Ranking wrapper determines final by max scheduled stage number. Prize finalizer determines final by absence of later non-cancelled stages. Do not silently reconcile these differing behaviors.
- Core finalizer locks stage and associated run, returns already_published when completed with authority/publication, requires hidden unapplied output and replay-live state, canonical stage start + at least 30 game minutes AND closed real replay window. Refuses existing partial outputs. Persists rider state and effects (fatigue, supplies, wear, health), results/points/events, completes run, creates authoritative run, calls **V1** classification writer, international points, prize generation, payment, final race/applications completion, then publishes. V1 uses synchronized stage bonus/points fields and per-stage adjusted time clamp; V2 uses canonical point rows and audited replacement. Prior 032 preview followed V2, not the actual core finalizer's V1. Need explicit V1 adapter and equivalence checks.
- Original fatigue writer assigns bounded integer fatigue_after_stage from authoritative rider-state rows for finished/DNF/OTL only, not DNS. Gate verifies daily recovery receipt and nonstale rider fatigue. Late-stage one-night correction uses prior official fatigue; base recovery max(3, round(4 + bounded recovery skill * .07 + morale modifier)), morale +1 at >=80, -1 below 40, plus activity and doctor bonuses; developing team with active residential campus receives 5% rounded recovery uplift. Subtract recovery from prior fatigue, add nonnegative travel impact, clamp 0–100. Starting stamina adjusted by fatigue delta * .45 and bounded 1–100. Requires calendar/tick/official rider-state inputs; same day no overnight; multi-day correction refused. Not equivalent to synthetic 029 energy loss rule.

## Live schema metadata — 21 allowlisted relations

Inspected column names/types/nullability, PK/unique/FK/check definitions and unique indexes, RLS flags. No relation data read. Relevant keys:
- One authority per stage (PK stage_id, UNIQUE simulation_run_id); stage automation PK stage_id.
- Stage results unique (simulation_run_id,rider_id) when run ID nonnull; otherwise unique (stage_id,rider_id). Rider-state unique (simulation_run_id,rider_id). Participant unique (race_id,rider_id). Point results unique (point_id,rider_id); one START and one FINISH point per stage via partial indexes.
- Classification snapshot unique (race_id,after_stage_id,classification_type,entity_type,rank); previous_rank and integer total/gap/points columns. Result elapsed/rank nullable, bonus/penalty/finish/sprint/mountain points nonnull integers. Need authoritative point generation and youth eligibility inputs.
- Prize award unique (race_id,stage_id,bucket_key,rank,recipient_type,team_id,rider_id), status pending/paid/cancelled, nonnegative bigint amount. Stage_id and rider_id nullable. Ordinary PostgreSQL UNIQUE treats NULLs as distinct; team-level awards with NULL rider_id may evade the unique-source key. Ranking unique (race_id,stage_id,source_type,rank,team_id,rider_id), nonnegative points. Require synthetic tests with nullable keys and explicit no changed paid amounts; do not copy a potentially unsafe retry contract.
- Prize bucket PK (race_class_code,bucket_key), numeric(6,3) share, JSONB rank distribution, positive top_n. Ranking rule PK (race_class_code,source_type,rank), nonnegative integer points. Category PK race_class_code. Entry rules PK race_id, nonnull bigint prize fund and source.
- Finance event lock PK (event_type,club_id,ref_id) with transaction reference. Transactions PK id, unique created_by/idempotency_key; accounts unique owner/system/currency/kind; entries bigint amount, transaction/account FKs. Transaction-types PK code with taxable flag and rate basis points. Daily tick PK (season,month,day).
- All 16 inspected public relations and finance accounts/entries/transactions have RLS enabled, finance event_locks/transaction_types do not. None of the 21 observed relations had FORCE RLS. This is metadata evidence only, not a conclusion about deployed access or an authorization to replicate ACLs. Isolated implementation must enforce least privilege separately.
