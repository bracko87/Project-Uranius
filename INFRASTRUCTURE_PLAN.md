## Worker and schedule preparation

The proposed execution contracts below are for U5.04–U5.06. Keep the existing offline worker path selectable, the test frontend loopback-only and all scheduled processing dormant during U5.01–U5.05.

- **Scheduler.** A separate local process polls due synthetic calendar rows every 30 seconds using database time and calls a narrow enqueue operation. Deduplicate by stage and schedule revision. Expiry, cancellation and paused world checks precede enqueue. Never activate copied production schedules or require pg_cron or outbound HTTP. With the local host asleep, jobs wait until the scheduler resumes.
- **Runner/recovery.** Claim a queued job atomically with a short lease and fencing token, then read immutable inputs and latest checkpoint outside the claim transaction. Start at a 120-second lease with a 30-second heartbeat from a responsive coordinator. Run heavy engine calculations in its child/worker thread. Renew using token and database time. Reject stale write attempts even if the old process resumes. Retry transient failures with bounded exponential backoff and move persistently failing jobs into an inspectable failed state. Define the restart limit and test lease expiry before enabling the schedule.
- **Commands/timeline.** Validate user, owned rider, cutoff and command idempotency. Assign the next sequence in a short transaction, separate receipt from application, and process against latest committed state. Keep future output private. On revision change use compare-and-swap on run revision, lease fence and command cursor. Preserve and hash elapsed frames/events, atomically replace the future suffix, and expose only newly elapsed deltas with cursors. A reconnect from an obsolete revision must receive the current revision and elapsed cursor, with no hidden data.
- **Results.** Use one fenced transaction to record the final authoritative revision, rider ranks/times, stage and team records, carryover and accounting entries. Use unique keys per logical result effect. Handle a lost response, retry, duplicate job and crash before or after commit. Reveal results only after the finish cutoff and successful finalization.
- **Run and rollback.** Start with a manual single-stage job and one worker before enabling the local scheduler in U5.06. Record local process arguments, environment field names and evidence with secrets omitted. To roll back, stop enqueue, drain or safely release leases, stop workers, preserve ledger/results and revert only reviewed schema changes or restore from sandbox backup. Verify target identity before each privileged action.

## Approved migration role bootstrap

A pre-existing role is an unexpected state and must stop the bootstrap. Set the password through the client password prompt before enabling LOGIN in the same transaction.

```sql
CREATE ROLE uranius_migrator NOLOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE
  NOINHERIT NOREPLICATION NOBYPASSRLS;
GRANT CONNECT, CREATE ON DATABASE postgres TO uranius_migrator;
GRANT USAGE ON SCHEMA auth TO uranius_migrator;
GRANT REFERENCES (id) ON auth.users TO uranius_migrator;
GRANT EXECUTE ON FUNCTION auth.uid() TO uranius_migrator;
```
